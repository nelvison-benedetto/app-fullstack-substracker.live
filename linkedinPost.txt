Built, deployed, and already used by 200+ real users.
SubsTracker is not a demo project — it’s a production-tested system designed with the same architectural principles used at scale (Uber, Stripe, Shopify).

I approached it as a blueprint for real-world backend + frontend systems — focusing on scalability, reliability, and clean design.

—

⚙️ 𝐁𝐚𝐜𝐤𝐞𝐧𝐝 𝐒𝐭𝐚𝐜𝐤
ASP.NET Core (.NET 8)
PostgreSQL + EF Core
Clean Architecture + DDD + CQRS
Vertical Slice Architecture
MediatR (internal orchestration)
        API
       /   \
Application  Infrastructure
      \     /
        Domain

🏗️ 𝐁𝐚𝐜𝐤𝐞𝐧𝐝 𝐊𝐞𝐲 𝐄𝐧𝐠𝐢𝐧𝐞𝐞𝐫𝐢𝐧𝐠 𝐂𝐨𝐧𝐜𝐞𝐩𝐭𝐬
• Domain-First Design
The domain is the source of truth — not the database.

• Vertical Slice Architecture
Each use case = isolated module (like a mini microservice):
Login / Register / CreateSubscription / etc.

• CQRS Mindset
Writes → Aggregates
Reads → Batch loaders (no heavy joins)

• Domain Events + Outbox Pattern
Reliable side effects (e.g. user created → email sent)
→ single transaction, no inconsistency risk

• Pipeline Behaviors (MediatR)
Validation → Logging → Performance → Transactions → Handler
Clean, centralized cross-cutting concerns

• Unit of Work (centralized)
Only one SaveChangesAsync() at the end of the pipeline

• Request-Scoped Cache
Avoid duplicated queries within the same request

• Infrastructure Abstraction
Everything external = behind interfaces (Ports)

• Pre-Signed Url
Secure, scalable file uploads without passing through the backend:
→ Backend generates temporary upload URL
→ Client uploads directly to Cloudflare R2
→ Backend confirms and persists metadata
→ Reduced server load + improved performance

• Middleware at the Edge
